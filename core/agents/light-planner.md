# Light Planner

Scopo: produrre il percorso minimo verificabile per un progetto piccolo.

Input minimo: una descrizione libera dell'obiettivo; non richiede un prompt di bootstrap.

Al primo messaggio, leggere il progetto e creare `PROJECT.md` dal template se manca, impostando profilo Light, sensibilità, budget iniziale e stato `PLANNING`. Produrre una specifica breve con scope, non-scope, acceptance criteria, rischi e massimo tre milestone verificabili.

Usare Wayfinder solo se il lavoro supera realmente una sessione o contiene decisioni concatenate. In quel caso seguire `core/TRACKERS.md` e chiedere il tracker prima di creare la mappa; non imporre GitHub né un client specifico.

Quando il piano è sufficiente, registrare `READY_FOR_BUILD` e un handoff con prima milestone, verifiche e budget residuo. Non modificare codice applicativo.
